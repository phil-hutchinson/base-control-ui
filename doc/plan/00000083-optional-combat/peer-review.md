# Peer Review — Story 00000083, Combat off or on

## Summary

The branch makes combat a pre-play choice: `rules.md` moves 0.33 → 0.34 in its
own commit, `GameState.combatEnabled` carries the setting from a fifth start
screen group through `useAppScreen` and the `new-game` intent, and a single
`"combat-is-off"` check at the top of `attackRefusalReason` refuses every
attack when it is off. The gate really is single — `legalTargets`,
`applyAttack`, `session.ts`, `Board.tsx` and `canMoveOrAttack.ts` all inherit
it with no production change of their own, and no other path reaches §7
behaviour — and the ~28-file test sweep is inert by construction, with the new
tests pinning the off behaviour at the rules, session, board and app layers
rather than merely passing.

`npm run typecheck` — clean. `npm run lint` — clean. `npm test` — 65 files,
1236 tests, all passing. (`npm run format:check` was also run: only the two
pre-existing baseline warnings, `doc/plan/00000069-retire-actions/story.md` and
`src/board/planetArt.ts`.)

Peer review fixes applied: `npm test` now 65 files, 1237 tests (the one new
off-game case from #10), all still passing; `npm run typecheck`, `npm run
lint` and `npm run format:check` unchanged from the above.

Findings are all documentation-level. Two Major ones are sentences in
`rules.md` that the app can contradict or that contradict another section; the
rest are Minor. Nothing in the code implements a rule the document does not
state, and nothing in the app still assumes fighting exists beyond the wording
the story deliberately left alone (S10).

## Checks made that found nothing

Recorded so a re-reviewer does not repeat them.

- **The single gate.** Every path to §7 behaviour goes through
  `attackRefusalReason`: `applyAttack` calls it first; `legalTargets`'s final
  filter keeps only squares it approves; `session.ts` reaches combat only via
  `legalTargets` (`targetCount`) and `applyAttack`; `Board.tsx` via
  `legalTargets` and `shipCanMoveOrAttack`; `canMoveOrAttack.ts` via
  `legalTargets`. `attackReach` is geometry and is reached only after the
  gate. `relief.ts`, `trap.ts`, `endOfTurn.ts` and `charging.ts` consult
  movement and the trap only. No second gate was added anywhere, as D3
  required.
- **Ordering.** `"game-over"` is still answered ahead of `"combat-is-off"`,
  and both precede every attacker- and target-side check, so an off game never
  answers "out of range" or "cannot afford" — pinned by three cases in
  `combat.test.ts`.
- **Rules versioning.** `rules.md` 0.34, `RULES_VERSION` 0.34 and one
  changelog entry all moved in commit `23dbea1`, ahead of the code, with
  `rulesVersion.test.ts` asserting both. No tag, per S7. `rules.md` contains
  no "standard game" or "default" language, for combat or anything else.
- **The sweep.** All 28 swept files set `combatEnabled: true`; no existing
  expectation changed anywhere, including `seededReplay.test.ts`'s recorded
  figures. The two unswept `startingGameState` call sites outside
  `gameState.test.ts` (`ply.test.ts#L320`, and a mention inside a comment in
  `Board.test.tsx`) exercise no attack.
- **The off tests bite.** `combat.test.ts`, `ply.test.ts` (state compared
  whole via `structuredClone`), `canMoveOrAttack.test.ts`, `session.test.ts`
  (`result.state` identity and surviving selection), `Board.test.tsx` and
  `App.test.tsx` each assert the same fixture both ways, so they pin the
  setting rather than the position.
- **README step.** Step 10 covers `README.md` and was run together with
  `/update-readme`; the README now introduces combat as a pre-play choice and
  says the app starts with it off.
- **Accessibility.** Nothing on this branch appears to cost an accessible
  behaviour, and per `CLAUDE.md`'s pre-release stance none is raised here.
