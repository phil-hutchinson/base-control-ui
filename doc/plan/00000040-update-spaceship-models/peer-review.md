# Peer Review — 00000040 Update spaceship models

## Summary

The branch replaces the flat `ShipIcon` silhouettes and their four-arc shield
ring with fully drawn models lifted from `.local/eg_spaceship.html`, declared
once in a hidden `<defs>` sprite (`src/ships/ShipDefs.tsx`) that every ship
`<use>`s, plus a four-slot shield gauge drawn per ship from
`src/ships/shieldGauge.ts`. `ShipIcon` and `shieldArcs` are deleted, the board
switches to `ShipModel`, and a document-wide id-uniqueness assertion covers the
story's section 2. The story's section 3 (ships on the start screen) was built,
shown to the owner and withdrawn; `src/start/` is byte-identical to `main` and
the revert left nothing behind in the source tree.

I checked the port element-for-element against `.local/eg_spaceship.html` —
every gradient, stop, path, ellipse, circle, line, rect, group, opacity and
stroke width matches, in the same order, with only the id renames and the
JSX-attribute conversion the plan permits. The gauge data (slot pitch
10/33/56/79, y=3, stroke widths 3.4/1.5, bars at y=25 from x=2.5 to x=13.5 at
widths 8 and 6, and both palettes) matches the source's worked examples exactly.
No rule logic is touched, and `rules.md`, `RULES_VERSION` and the changelog are
correctly left alone.

`npm run typecheck` passes. `npm run lint` passes. `npm test` passes (44 files,
770 tests). `npm run format:check` — which every step's verification claims
passes — **fails** on this story's own `implementation-plan.md`; see comment 4.
