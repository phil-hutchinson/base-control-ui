# Peer Review — 00000037 New combat rules, and nodes that run their course

## Summary

The branch takes the ruleset to 0.16 and rewrites combat around a single
outcome: every fight sends both ships to randomly drawn bays at 0 shields, a
ship standing on a charged node can neither attack nor be attacked, and §8.7's
vacating rule is deleted so a node that is left standing empty stays lit and
burns on at the empty rate until its drain reaches capacity. The code follows:
`resolveFight`, `FightOutcome`, `winnerAdvance`, `AdvancingWinner`,
`PredictedFightOutcome` and the whole `vacating.ts` module are gone,
`applyAttack` collapses to one path, `runEndOfTurn` derives its own
start-of-ply dormant set, and `README.md` and the board's wording follow. The
work is disciplined and the rules-first ordering of steps 1 to 8 held; the
deletions took nothing with them that the remaining tests do not still prove.

Checks run from the repository root: **`npm run typecheck` passes**,
**`npm run lint` passes**, **`npm test` passes (43 files, 762 tests)**. No
findings were filed from those three.

Two things are noted as known history rather than raised as findings. First,
the story's Verification bullet still says a ship arriving on an already-lit
node collects "from the end of its owner's next turn"; the ruleset (§8.6 steps
1 and 2 run after the player's action) says it collects at the end of that same
turn, step 7's tests assert the ruleset's behaviour, and the correction is
recorded in step 7's Notes. Second, step 10 (renaming the result panel's button
to "New Game") is owner feedback from step 9's gate, not part of the ruleset
change; it touches no rule logic and is correctly scoped.

The implementation plan does include a step that checks `README.md` is still
current (step 8, with its own repository-wide sweep), so no comment is raised
on that.
