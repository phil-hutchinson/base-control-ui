# Peer Review — Story 00000101, Steal: a fourth node playstyle

## Summary

The branch renames the start screen's "Inactive node rotation" group to
"Node playstyle" and adds a fourth setting, STEAL. STEAL gets its own ruleset
companion, `doc/ruleset/steal.md`; the ruleset moves to 0.39, and
`RULES_VERSION`, the changelog and `CONTRIBUTING.md` move with it. On the rules
side it adds a steal opening deal, the weighted prospective-square draw
(strict-pool first for the opening deal's second square), claim and abandon
events in `applyMove`, and an end of turn that runs only power and energy. On
the view side it adds signal colours on the board, the claim charge animation,
live-region sentences, a STEALING NODES Quick Guide section with a diagram, and
a README update. The rule logic matches `steal.md` on every point I checked:
claim, abandon, the abandon-then-claim order, relocation, the draw's anchor and
`S`, edge halving, the strict-first opening, the 2N-step deal, and steps 1–2
only at the end of a turn. I found no Critical findings. Most findings are
about test reliability and documentation hygiene.

Checks run from the repository root:

- `npm run typecheck` — clean.
- `npm run lint` — clean.
- `npm test` — **1 failed / 1645 passed** (80 files). The failure is a
  5000 ms timeout in `src/rules/stealPlacement.test.ts` (the 5-node opening
  distance-band test). Run alone, the same file passes in about 14 s, with
  single tests taking up to 3.5 s. It is a load-sensitive timeout, not a logic
  failure (see #1).
- `npm run format:check` (also run, because the plan requires it) — clean.

The plan includes a README verification step (Step 11), and it is committed.
