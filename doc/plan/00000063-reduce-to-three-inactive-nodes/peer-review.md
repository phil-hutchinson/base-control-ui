# Peer Review — Story 00000063, three inactive nodes and a priority you can read

## Summary

The branch replaces the eight-node pressure-weighted inactive pool with a queue
of exactly three inactive nodes carrying priorities 1, 2 and 3: charging is
deterministic and top-down, priorities rotate on a turn that charges nothing,
any charge sweeps the queue and refills it by a distance-weighted draw from a
pool that widens once, a fourth charged node is placed directly when all four
run out at once, pressure and one-out-one-in replacement are gone, and the
inactive marker is redrawn as concentric rings. `rules.md` moved to 0.26 in its
own commit ahead of the code, with `RULES_VERSION` and a single changelog entry
alongside it (no tag, correctly), and Appendix B was later corrected in the same
entry against Step 7's measurements.

Checks from the repository root: **`npm run typecheck` passes**, **`npm run lint`
passes**, **`npm test` passes (57 files, 1010 tests)**. No findings arise from
those three.

The rules layer matches `rules.md` 0.26 as far as I could check it: the four-seed
step refill order stated in `nodeQueue.ts` matches the code and is asserted in
`nodeQueue.test.ts`; the opening deal's 12 steps match `nodes.ts`'s header and
are asserted in `nodes.test.ts`; charging consumes no randomness and the direct
fourth placement consumes exactly one step; the widened pool never opens the
outer edge; and `nodePool.test.ts` drives the three-inactive, four-charged and
placement-legality invariants over 500 plies across five seeds. I found no
correctness or rules-fidelity defect. Everything below is Minor: stale or
convention-breaching comments, dead code, one README claim the plan's own Step 9
called for and did not land, and two documentation loose ends.
