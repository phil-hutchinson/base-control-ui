# Peer Review — Story 00000122, Core package and release

## Summary

The branch moves every random draw in the rules onto a caller-supplied
`RandomSource` (`seededRandom` / `recordedRandom` / `DesyncError`). It takes
the seed out of `GameState` and gives it to the app's `Session`, and adds the
core entry point `src/core/` (`parseSetup`, `startGame`, `parsePly`,
`formatPly`, `applyPly`, `toMove`, `result`, `canonicalState`, `stateHash`,
`CORE_BUILD`). It also adds a no-DOM `tsconfig.core.json`, an ESLint import
boundary, the `build:core` / `pack:core` / `smoke:core` scripts, a replay
measurement recorded in `tech-notes.md`, the hand-run `core-release`
workflow, and documentation. The ruleset is untouched, and the seed-pinned
expectations in the existing suites (`seededReplay`, `fullGame`,
`gameState`, `ply`, …) are unchanged, so the draw order was kept exactly as
it was. The work follows the plan closely. Step 9's manual verification
(running the workflow) is deferred to after merging by owner decision, so
this review does not count it as a finding.

Checks run from the repository root on `2d84dcd`:

- `npm run typecheck`: passes, no errors.
- `npm run lint`: passes, no findings.
- `npm test`: passes, 98 files and 2159 tests.

The reviewer also ran `npm run build:core`, `npm run pack:core` and
`npm run smoke:core -- dist-core/core-2d84dcd.tgz` on the clean tree. All
three passed: the smoke test reached the pinned hash `92eca44a0af5bd46`, and
the tarball holds only `package.json`, `index.js` and `types/`.

Ruleset check: no rules file changed and none needed to, so `RULES_VERSION`
and the changelog correctly stay where they were. The rule logic changes only
how draws are delivered, never what is drawn. The plan includes the README
check (Step 10).
