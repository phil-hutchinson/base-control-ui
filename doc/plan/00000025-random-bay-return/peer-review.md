# Peer Review — 00000025 Random bay return

## Summary

The branch replaces the numbered, drifting bay ring with a seeded random draw
over the bays standing empty: `drawReturnBay` in `src/rules/combat.ts` returns
the drawn bay and the advanced seed, `applyAttack` threads that seed through
both return paths, the ring (`CLOCKWISE_BAYS`, `returnPositionIndex`,
`driftReturnPositionIndex`, `bayNumberingFrom`, §8.7 step 6) is deleted, and
both on-board return cues and their accessible-name wording are removed.
`rules.md` 0.9 → 0.10, the `RULES_VERSION` constant and the changelog entry all
moved together in a single commit (`7794607`) ahead of the code, as D1 requires,
and the rules text as written matches the implemented behaviour — the draw is
uniform over the empty bays in a fixed `BAYS` order, the mutual return draws the
attacker first against a state carrying both the attacker's new square and the
first draw's advanced seed (D5 holds), and §7.1's "always somewhere to go"
argument is sound given §7's rule that a ship in a bay can neither attack nor be
attacked. Step 6 also touched `CLAUDE.md`'s "Game records" paragraph beyond the
plan's literal wording; that deviation is recorded in the step's Notes, so it is
not raised below.

`npm run typecheck` passes. `npm run lint` passes with no findings.
`npm test` passes: 42 files, 668 tests, all green.
