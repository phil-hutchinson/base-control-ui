# Peer Review — Story 00000090, How the waiting nodes rotate

## Summary

The branch turns inactive-node rotation into a seventh pre-play choice
(continuous, planet, dedicated), adds rotators as new board furniture under the
dedicated setting, moves the rotation trigger out of the end-of-turn sequence
and into a landing under two of the three settings, and carries the choice
through the rules document, the state, the reducer, the start screen, the
board's artwork, the live region, the Quick Guide and the README. All fifteen
plan steps are committed, including the owner's manual gates at steps 8–11, 13
and 15.

Verification from the repository root: `npm run typecheck` **passes**,
`npm run lint` **passes** (no findings), `npm test` **passes** (72 files, 1414
tests). `npm run format:check` was also run and reports only the three
pre-existing baseline warnings the plan records, none of them from this branch.

The rules work checks out: `rules.md` moved 0.35 → 0.36, `RULES_VERSION`
matches, and one changelog entry covers the whole change, including Step 11's
later nine → six revision folded into the same bump as the project requires.
Section 8.2, the new section 3.3, section 8.6 step 5 and its closing notes,
section 7, section 1's overview, section 8.1 and section 10 all agree with
what the code does; I found no rule logic in `src/` that contradicts the
document or that implements a rule the document does not state. The plan
included a README step (Step 14). The findings below are documentation
staleness and comment-convention breaches, not correctness bugs.
