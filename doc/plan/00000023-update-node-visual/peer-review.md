# Peer Review — 00000023 Update node visual

## Summary

The branch replaces the site-state markers with the six supplied SVG samples,
adds `siteCyclePosition` to `src/rules/sites.ts` so a charged or depleted
site's middle gradient stop travels across its nine-turn clock, threads the
square name down to `SiteMarker` so each of the seventeen gradients gets a
unique id, and removes the marker's own 2px state-coloured border. The artwork
transcription matches `node-artwork.md` exactly (radii, stops, colours,
opacities, `cx`/`cy`/`r`, dropped clip path), the cycle arithmetic agrees with
`hasChargedNodeFinished` / `hasDepletedSiteFinishedCooling` and with
`nodes.ts` / `endOfTurn.ts` as decision D6 sets out, nothing time-driven was
added (no transition, keyframe, timer or wall-clock read), the offset is
calculated rather than tabulated, and the grid and bay borders are untouched.
No rules change was made and none was needed, so `rules.md`, `RULES_VERSION`
and the changelog correctly stand still.

`npm run typecheck` passes, `npm run lint` passes, `npm test` passes (688
tests, 41 files); `npm run format:check` also passes. No Critical or Major
findings. The plan does contain a README step (step 6), so no finding is
raised there.

On the two points referred for independent judgement:

- **The ledger's story-23 item 2** is over-scoped as written — it describes a
  visual change without naming an accessibility cost, in a document
  `CLAUDE.md` says is not an audit. Raised as comment 1. It is fixable by
  saying what was lost rather than by deleting it.
- **The README clause** is warranted: the story genuinely gives a player
  information they could not previously read off the board, and the status
  paragraph is where the README lists that. The wording is plain, hedged
  ("roughly") and free of jargon, so it reads correctly for a non-technical
  player. One small accuracy caveat is raised as comment 6.
