# Peer Review — 00000041 Power replaces shields, and bays recharge over time

## Summary

The branch renames a ship's number from shields to power, reverses its
polarity (`power = 4 - shields`), stops a fight changing either ship's power,
and turns a bay's instant refill into a point-per-turn recovery at the same
end-of-turn step a dormant site uses. `rules.md` moved to 0.17 with a matching
`RULES_VERSION` bump and a single changelog entry in its own commit ahead of
the code, and the rule logic in `endOfTurn.ts`, `movement.ts` and `ply.ts`
matches the document section for section — I found no contradiction with
`rules.md` and nothing implemented that the document does not state. The
mid-story correction (writing `MAX_POWER` rather than a literal `0` where the
old code reset a ship) is the faithful conversion and is correctly reflected
in both the plan text and the code; `movement.test.ts`'s expected square lists
are byte-identical, which is the evidence the reskin is a reskin.

`npm run typecheck` passes, `npm run lint` passes, and `npm test` passes (45
files, 779 tests); `npm run format:check` is also clean. All findings below are
Minor.

On the two questions raised: (1) the `actionsRemaining: 2` fixture in
`ply.test.ts` buys its isolation with a state that cannot arise in play, and
there is a cheaper seam that needs no impossible state — see comment 1; (2) the
`endOfActionSettlements` extraction in `EnergyOverlay.tsx` is the right fix
(it sidesteps the union-of-array-types narrowing gap without changing
behaviour, and `EnergyOverlay.test.tsx` passing unedited is good evidence of
that) and step 5 is the right place for it, since it is `MoveEffect`'s
collapse in that step that breaks the old code and every step must typecheck
on its own. No change requested there.
