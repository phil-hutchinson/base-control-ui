# Peer Review — 00000009 Nodes: waking, charging, depleting

## Summary

This branch brings the board to life: a seeded `mulberry32` generator, a ply
counter and per-site clocks in `GameState`; §8.2 waking on touch and §8.6's
random replacement in a new `nodes.ts`; §8.7's six-step end-of-turn sequence in
a new `endOfTurn.ts`; §8.5's stranded-ship obligation in a new `stranded.ts`
with a new refusal reason; wording for every new event; and a board layer that
generalises the dampened shade to "no action available" and blinks a ship that
owes an action. The ruleset moved twice with the owner's rulings (0.3 → 0.4, a
ship on a dormant site is stranded too; 0.4 → 0.5, the freeing move is the
first action), each with a changelog entry, a `RULES_VERSION` bump and no tag,
which is correct while tagging is on hold. The clock arithmetic, the §8.3
five-collections and opponent-moves-next properties, the eighteen-ply round
trip, the draw, the safety net and the Appendix B guard are all implemented as
the document states and covered by tests.

Verification from the repository root: **`npm run typecheck` passes**,
**`npm run lint` passes**, **`npm test` passes** (28 files, 348 tests, ~31 s).
`npm run format:check` and `npm run build` were also run and pass. No rule
logic was found that contradicts `rules.md`; the findings below are one
performance/design problem, one rules-document gap the code has settled on its
own, and a set of comment-convention and wording items.
