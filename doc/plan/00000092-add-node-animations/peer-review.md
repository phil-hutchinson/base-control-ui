# Peer Review — Story 00000092, The board moves

## Summary

The branch adds three CSS-only board animations — a node lighting up, a node
burning out, and the rotators turning — driven by one new pure module,
`src/board/boardAnimations.ts`, that maps a session's last event to at most one
animation per square. The only `src/rules/` change is a reporting field
(`priority` on `NodeChargedEffect`); `rules.md`, `changelog.md` and
`RULES_VERSION` are correctly untouched, and the plan's Step 8 covers the
`README.md` check. `npm run typecheck` passes, `npm run lint` passes, and
`npm test` passes (73 files, 1452 tests); `npm run format:check` reports only
the three pre-existing, out-of-scope warnings.

The D5 end-state guarantee holds everywhere I could exercise it: every animated
element's base style is the finished artwork, each animated subtree is keyed so
that losing the animation forces a remount, and three `innerHTML`-equality tests
pin the interrupted case. Two behavioural findings remain, both about the
animation showing something the board was not showing a frame earlier: the
burnout's gradient offset does differ on the `node-spent` road that Step 7
added (D6's proof does not survive it), and the charge animation fades a ring
count that can differ from the one the player was looking at under the `planet`
and `dedicated` rotation settings.
