# Peer Review — Story 00000085, Simple or bonus scoring

## Summary

The branch makes scoring a pre-play choice (SIMPLE or BONUS) in the shape the
other five options already have: `rules.md` moves to 0.35 with a matching
`RULES_VERSION` and one changelog entry, a new leaf module `src/rules/scoring.ts`
holds the settings, `energyForNodesHeld` returns to `src/rules/energy.ts` as the
one pricing function, `GameState.scoring` carries the setting through the
`new-game` intent and `useAppScreen`, the HUD's pip row gains a number under each
pip, and the Quick Guide's scoring diagram becomes a two-row rate table. The work
follows the plan closely — every step carries a `Notes:` line, the three
owner-requested mid-flight changes (the start screen's legend gap, the greyed pip
numbers, the guide grid's NODES corner and legend line) are recorded as
decisions, the one accepted accessibility cost is in
`doc/plan/00000021-accessibility-tech-debt/known-issues.md`, and
`seededReplay.test.ts` is correctly untouched — nothing in the diff adds a draw
to the seeded stream. The plan does include a README step (Step 13), and it was
carried out.

Checks run from the repository root at review time:

- `npm run typecheck` — **clean**.
- `npm run lint` — **clean**.
- `npm test` — **green, 66 files, 1278 tests**.
- (`npm run format:check`, not required by the review but tracked by the plan —
  only the two pre-existing warnings, `doc/plan/00000069-retire-actions/story.md`
  and `src/board/planetArt.ts`.)

Spot checks asked for, and their results: `energyForNodesHeld` is the only
function that prices a payout and `endOfTurn.ts` is the only site that pays
anybody (`ScoreDisplay` and the guide table both ask hypothetical questions);
nothing else in `src/` touches `state.energy`. `rules.md` 0.35 and the code agree,
and no remaining section of the document states one rate as the only rate
(§1, §2, §8.1, §8.3's table, §8.5, §8.6 step 2 and §9 were all re-read). The
`GuideDiagram` additions really are opt-in — the modifier class, the
`--guide-diagram-data-columns` custom property and both new cell kinds are
reached only when a caller passes `labelColumn` or a `label`/`rule` cell, and the
other four diagrams' existing assertions pass unchanged. The `--region-extent`
re-derivation in `App.css` is arithmetically correct against what
`ScoreDisplay.css` actually sets (pip `0.6em` + column gap `0.1em` + `1.5 x
0.55rem` line = `1.525rem`; three in-flow children, so still two `0.25rem` cell
gaps; new sum `10.65rem .. 15.9rem` and the clamp moved by the same flat
`0.925rem` at both ends).

The findings below are all documentation or presentation-level; none of them is a
correctness defect.
