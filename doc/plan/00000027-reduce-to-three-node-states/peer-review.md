# Peer Review — 00000027 Reduce to three node states

## Summary

This branch collapses the four site states into three (`active`, `charged`,
`dormant`), deletes waking-on-touch outright, and moves charging to a
board-driven end-of-turn draw that tops the charged count back up to five.
`rules.md` moved 0.10 → 0.11 in its own first commit with a matching changelog
entry and `RULES_VERSION` bump, the section renumbering of D2 was applied
cleanly, and the rename rotation (`dormant` → `active`, `depleted` → `dormant`)
was carried through correctly at every consumer I checked —
`moveLegality.ts`, `combat.ts`, `stranded.ts` (the untyped `Set<string>` trap),
`SiteMarker.tsx`, `announcements.ts` and the session/board tests all map the
right way round, and no `depleted` or wake machinery survives in `src/`.

Verification from the repository root: `npm run typecheck` **passed**,
`npm run lint` **passed**, `npm test` **passed** (41 files, 667 tests). The
implementation plan does include a README step (step 6), which was carried out.

The rule logic matches `rules.md` 0.11 everywhere I traced it — both nine-ply
clocks, the five end-of-turn steps with cooling last, the shortfall draw
without replacement off the seeded generator, the two refusal reasons, the
stranding states and the staggered opening — so there are no Critical findings.
The findings below are a stale clock comment that contradicts §8.3, two gaps
between the planned/story-listed verification and what the suite actually
asserts, and a handful of vocabulary and comment-convention leftovers.
