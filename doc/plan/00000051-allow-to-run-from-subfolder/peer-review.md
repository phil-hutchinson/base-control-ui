# Peer Review — 00000051 A build that runs from a subfolder

## Summary

The branch does exactly what the story and plan describe and nothing more: `vite.config.ts`
gains `base: "./"` with a seven-line explanatory comment, and `CONTRIBUTING.md`'s
"Architecture constraints" section gains one paragraph on the relative base, the
trailing-slash hosting condition and the no-root-absolute-URL rule. No file under `src/`,
no test, no dependency, no `index.html` and no ruleset file is touched, and `README.md` is
untouched as decided (D8). `npm run typecheck` passes, `npm run lint` passes,
`npm test` passes (53 files, 898 tests); `npm run format:check` also passes.

Verified independently while reviewing: a fresh `npm run build` emits
`./assets/index-*.js` and `./assets/index-*.css` with no root-absolute URL anywhere in
`dist/`; the built folder served from a nested subfolder (`/a/b/`) fetches its assets from
`/a/b/assets/…` with a 200, and `/a/b` without the slash gets a 301 to `/a/b/`;
`vite preview` still serves a working page at the server root. The one recorded departure
from the story's verification list is that the owner chose not to play a full game through
to the game-over panel in the subfolder (Step 2 Notes), on the grounds that the app makes no
request after load — the single-chunk build confirms there is no later fetch the location
could affect, so the substitution is sound and it is documented, and it is not raised as a
finding below.
