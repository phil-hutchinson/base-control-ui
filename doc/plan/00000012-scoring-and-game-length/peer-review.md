# Peer Review — 00000012 Scoring and game length

## Summary

The branch delivers the whole story: rules 0.7 (influence → energy, §8.4's new
0/1/3/6/10/15 table, version, changelog and `RULES_VERSION` all moved together),
a new `src/rules/energy.ts` and `src/rules/gameLength.ts`, energy totals and the
game's length carried in `GameState`, §8.7 step 2 filled, the game-over refusals
with the pass-guard trap closed above the six-only/seven-only layers, a session
`new-game` intent, the arcade HUD in a new `src/hud/`, the floating `+N`
overlay, the result panel with play again, and the arcade chrome. The rules
layer matches `doc/ruleset/rules.md` §8.4, §8.7 and §9 everywhere I checked, no
module hardcodes 100 or 200, and the temporary review fixture has been removed.

`npm run typecheck` passes, `npm run lint` passes, and `npm test` passes (39
files, 614 tests). All findings below are code-quality, comment-convention or
document-consistency points; none is a rule-logic contradiction, and the plan's
decision 2 (the payout table stays data, not `n * (n + 1) / 2`) is respected and
deliberately not reported as a missed simplification.
