# Peer Review — 00000029 Variable node durations

## Summary

This branch replaces a node's fixed nine-turn life with a capacity of 60 and a
randomly drawn drain, gives dormant sites a randomly drawn recovery that
carries the drain they went dormant with, gives active sites pressure that
weights the end-of-turn charge draw, and adds §8.7's rule that leaving a
charged node ends it immediately. `rules.md` moves 0.11 → 0.12 in its own
commit with a changelog entry and a matching `RULES_VERSION`, `SiteStatus`
collapses onto one `level` field, `random.ts` gains a weighted index draw, a
new `vacating.ts` holds §8.7, and the active site's artwork gains a
pressure-driven travel between the shelved pale disc and today's gold disc.

All three checks pass from the repository root: `npm run typecheck` clean,
`npm run lint` clean, and `npm test` green at 725 tests across 42 files. The
implementation follows the plan closely; the three recorded deviations
(step 3's `siteCyclePosition` orientation, step 5's unreachable blocked-advance
end-to-end test, step 7's measured bounds) were each checked independently and
the first two are correct — see the notes under Comments. The plan does include
a README step (step 8), so no finding is raised for that. The findings below
are one weak long-run guard and a set of comment-convention and
document-wording points.

Independent checks performed while reviewing:

- Step 3's deviation is right. §8.5 of 0.11 and story 29 §5 both put the
  dormant travel at 0 when the site has just gone dormant (level = capacity)
  and 1 when it has recovered (level = 0), which is what `1 − level / capacity`
  gives; the plan's step-3 checklist item 10 was indeed a slip.
- Step 5's deviation is right. Every bay sits on the board's outer edge
  (column A, column O, row 1, row 15) and no site does, so no bay can ever lie
  strictly between an attack's origin and a site at the far end of its lane —
  a blocked advance onto a charged node genuinely is not constructible through
  `applyAttack`.
- Step 7's bounds were re-derived by simulating the no-ship economy
  independently; see comment 1.
