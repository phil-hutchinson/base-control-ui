# Peer Review — Story 00000105, Advanced planet bonuses

## Summary

The branch adds a fourth planet bonus setting, ADVANCED (steal only), and retires the six-a-side fleet. The pieces are: a new `advancedBonus.ts` leaf module (kinds, weights, point table, opening deal, claim resolution); extra prospective squares, Additional nodes and Node scramble in `steal.ts`; claims wired into moves and a reordered `applyAttack`; a two-cell bonus panel with four symbols; a live-region sentence; a Quick Guide section; a README update; and a measured rebalance of the point table. The ruleset moved together: `rules.md` 0.41, `RULES_VERSION` "0.41" and one changelog entry. The main problems are these. Node scramble under-fills an Open node that carries an extra, which contradicts steal.md §10 (Critical). The whole-game and seeded-replay coverage for advanced that the plan's Step 5 asked for was never written, and the Notes do not say so. That coverage would have caught the scramble defect.

Checks run from the repository root on `feat/105-advanced-planet-bonuses` at `16293d9`:

- `npm run typecheck` — clean.
- `npm run lint` — clean.
- `npm test` — 84 test files, 1796 tests, all passing.

Story vs plan: the plan adds three rules the story does not state. D8 is the anchor rule for a node with an extra. D9 is leave-before-claim on one move. D10 is that the defender still occupies its square while the attacker's claim resolves. All three are documented in the plan as gaps the story leaves, flagged for the owner, and written into steal.md §10, so the ruleset and the code agree. The plan includes a README step (Step 9), and it was carried out.

# Peer Review — Round 2 (owner feedback: Steps 11–12)

## Summary

This round covers the three commits after the first review. 562e783 revised story.md and added Steps 10–13 to the plan. e9b8573 (Step 11) made the ADVANCED panel larger: planets are sized from a new `--board-square-size` token, there is a one-word caption, Fuel is a single bar, and the row wraps. ef5fc11 (Step 12) added the hover glow, with a `useBonusHoverGlow` hook in `App`, a `glowSquare` prop on `Board` and a `board-square--glow` halo.

Checks run from the repository root on `feat/105-advanced-planet-bonuses` at `ef5fc11`:

- `npm run typecheck`: clean.
- `npm run lint`: clean.
- `npm test`: 88 test files, 1856 tests, all passing.

**Board size.** Switching `Board.css` from `100cqmin / 15` to `--board-square-size` does not change the board's size anywhere. `.board-frame` is rendered only inside `.app__play`. That box has no padding or border, has explicit `width`/`height: var(--play-size)` and `flex: 0 0 auto`, so its content box is exactly `--play-size` on both axes, which is what `100cqmin` measured. `--play-size`, `--region-extent` and the window-axis tokens are only ever set on `:root`, including the landscape media query, so the `:root` substitution matches the old per-element measurement. Nothing else in `src/` (outside `guide/` and `bonus/`, which have their own containers) reads a container unit against `.app__play`, so dropping its `container-type: size` is safe.

**Portrait layout.** This is the main problem this round (#12). The pair never wraps in portrait, and wrapping would not help there, because the limit in portrait is height. Each cell's stack is about 2.06 × its width tall. In most portrait windows it fits in the panel's share of `--region-extent` with only a pixel or two to spare, or is already a pixel or two over. Wherever a board square is wider than `0.3 × --region-extent` (a high-resolution portrait window), the panel's `overflow: hidden` cuts off the caption and part of the symbol.

**Glow clearing.** Clearing on a claim works, and it is tested. However, the effect only asks whether the square is still in the new state's panel set, and it runs after paint. A hover left over when the panel unmounts can therefore come back in a later game (#13), and the claimed square keeps its glow for one frame (#15).

**Ruleset.** No ruleset file, `RULES_VERSION` or changelog changed. The work is UI only and adds no rules.

**Story vs plan.** The two agree. Steps 11–12 match the revised story, and their Notes record the deviations (the hook/helper factoring, the new token, the guide-cell override). The plan still has its README step (Step 9), but none of Steps 11–13 checks README again for the new hover behaviour (#16).
