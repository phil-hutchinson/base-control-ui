# Peer Review — Story 00000060, A node's countdown starts when you step on it

## Summary

The branch replaces the drain/recovery model with a single fixed countdown
that runs only while a ship stands on a node: `src/rules/countdown.ts` is a
new leaf holding the three constants, the per-ply spend, the displayed number
and the artwork cycle position; `ply.ts` starts a countdown on arrival and
depletes a node on departure; `endOfTurn.ts` steps 3 and 6 spend plies
deterministically; `movement.ts` bars landing on any uncharged node;
`nodePlacement.ts`'s fallback no longer places a node under a ship; and the
fourth-node-placed-directly rule and the relief's random tie-break are
deleted. `rules.md` moves to 0.27 with a single changelog entry and
`RULES_VERSION` in step, and `src/board/NodeCountdown.tsx` draws the black and
white numbers. All nine plan steps are marked committed.

`npm run typecheck` — **pass**, no errors. `npm run lint` — **pass**, no
findings. `npm test` — **pass**, 59 files / 1024 tests. None of the three
produced a finding, so none is filed below on that account.

The arithmetic was checked against `rules.md` §8.3 row by row: the charged
row (`ceil(p/2)`, 6→1 over eleven plies, six holder turn ends, six energy
collections) and the trap row (`floor(p/2)` floored at 1, five trapped turns,
release at the opponent's turn end) both match the document's two worked
tables exactly, and the exit node's two plies land where §8.3 says. The
findings below are documentation staleness, an unrepresentative measurement
quoted as a rule-document figure, and gaps against the plan's own required
test cover — not rule-logic defects.
