# Peer Review — 00000033 Dormant sites cost energy and shields

## Summary

The branch takes `rules.md` from 0.13 to 0.14 in its own first commit (§1, §4.1,
§8.1, §8.4, §8.5, §8.6, with a changelog entry and a matching `RULES_VERSION`
bump), then implements the new rule across eight further commits: `energy.ts`
gains `dormantSitesOccupiedBy` and a clamping `energyForDormantSites` reading the
one existing table; `endOfTurn.ts` extends §8.6 step 1 with a floored shield loss
and step 2 with a floored energy penalty, raising two new effects; and
`announcements.ts`, `EnergyOverlay`, `ScoreDisplay`, `scoreSentence` and
`README.md` report both directions. `npm run typecheck` passes, `npm run lint`
passes, and `npm test` passes (42 files, 754 tests), including
`seededReplay.test.ts` unchanged.

The engine matches §8.4 and §8.6 as written. Collection runs before the penalty
inside one sequence and the two are not netted; the deduction is
`min(tablePrice, energyHeld)` and the effect reports exactly that, so
`newTotal === previousTotal - amount` holds on every path and `fullGame.test.ts`'s
ledger identity is exact rather than approximate; a zero deduction raises no
effect on either of its two routes, as D4 and the owner decided. `runEndOfTurn`
is the only settlement site and `applyPassGuard` is non-recursive, so a ply can
produce at most one settlement per side and none can be missed; nothing added
consumes a seed step, so the replay guarantee holds. The updated expectations in
`camping.test.ts`, `ply.test.ts`, `fullGame.test.ts` and the four `scoreSentence`
files are each genuinely falsified by the new rule rather than weakened — the
`ply.test.ts` change in particular follows from a winner advancing onto an
already-dormant site in the same action that ends its ply, and the `camping.test.ts`
"pays nothing" case was retitled and widened rather than deleted. The plan
included a README step (step 8). All findings below are Minor.
