# Peer Review — Story 00000059, A depleted node traps the ship on it

## Summary

The branch removes the depleted-node energy penalty end to end and replaces it
with the trap: `src/rules/trap.ts` derives who is trapped, `movement.ts` and
`combat.ts` refuse a trapped ship's move and attack (and refuse it as a
target), `endOfTurn.ts` reports `ship-trapped` / `ship-freed` and gains §8.6's
new step 7 relief driven by `src/rules/relief.ts`, and the HUD loses its
depleted pip row along with everything derived from its height. `rules.md`,
`RULES_VERSION` and the changelog all move together to 0.25 in one commit
ahead of the code, and `README.md`, the accessibility ledger and the test
suites follow.

`npm run typecheck` passes, `npm run lint` passes, and `npm test` passes (56
files, 983 tests). Every plan step is marked committed, each deviation is
recorded in its Notes line, and Step 11 covers the `README.md` check the plan
is required to include. No correctness defect was found in the rule logic; the
findings below are one gap in the rules document and a set of documentation
and comment-convention issues.
