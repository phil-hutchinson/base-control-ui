# Peer Review — 00000003 Set the site positions

## Summary

The branch takes `rules.md` from 0.1 to 0.2 (seventeen fixed sites with a board
diagram and a symmetry statement, the four states renamed to
dormant/active/charged/depleted, the starting five stated, §3.2's spacing
constraint restated as the property with the numbers demoted to a derived note,
Appendix A item 1 closed and Appendix B refreshed), adds `src/rules/sites.ts`
with the seventeen squares, the `SiteState` type and `startingSiteState`, and
draws the sites on the board through a new decorative `SiteMarker` whose four
appearances differ by ring treatment before colour, with the site state carried
into each square's accessible name. `rules.md` 0.2, the `## 0.2` changelog entry
and `RULES_VERSION = "0.2"` all move together in commit 8fb2da4; the temporary
`src/board/reviewFixture.ts` is fully gone (a repo-wide grep finds it only in
this story's plan document, as expected) and the plan includes the README step
(Step 13, done in a39977f).

Verification from the repository root: `npm run typecheck` **passes**,
`npm run lint` **passes** (no findings), `npm test` **passes** (96 tests, 13
files). `npm run format:check` and `npm run build` were also run and pass.

Nothing in `src/` was found to redefine or extend a rule the document does not
state: the seventeen squares, their canonical order, the four state names and
the starting five all match §3.2 and §8.1 line for line, the movement ranges
encoded in `siteSpacing.test.ts` match §6's 0-shield accumulation (1–3
orthogonal, 1–2 diagonal), and the derived thresholds in §3.2 (≥ 3 orthogonal,
≥ 2 diagonal) are exactly what excluding the origin square implies. No
Critical findings. The Step 9a appearance swap matches decision 1's amended
table (dormant = medium dashed over a darker fill, depleted = thin dotted with
no fill), and the story-versus-plan documents agree throughout.
