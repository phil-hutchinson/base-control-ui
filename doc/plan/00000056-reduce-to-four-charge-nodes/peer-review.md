# Peer Review — Story 00000056, Four charged nodes

## Summary

The branch takes the board's charged target from five to four and takes both
ends of §8.4's energy table down with it: `rules.md` 0.20 → 0.21 with a
matching `RULES_VERSION` and changelog entry, `TARGET_CHARGED_NODES = 4`,
`ENERGY_BY_NODES_HELD` truncated to `[0, 1, 3, 6, 10]` (so
`MAX_DEPLETED_NODES_PRICED` derives to 4), the over-cap announcement
interpolating that constant, both pip rows sized from constants, and the
long-run guards re-measured. The rules document, the constants and the tests
agree with each other, and every measured figure quoted in a re-measured
comment was independently reproduced during this review (lowest instantaneous
inactive 7, worst same-ply expiries 2, multi-expiry share ≤ 1.4%, longest wait
238 turns, 68–69 total charges, meanDepleted ~1.45 / meanInactive ~9.55,
seeded-replay counts 12 / 24 / 11 / 8) — with one exception noted below.

Verification from the repository root: `npm run typecheck` passes,
`npm run lint` passes, `npm test` passes (54 files, 938 tests). Story and plan
agree on substance; the two places they differ (the seeded-replay
"regeneration" and the spelled versus numeral cap in the announcement) are
both recorded as deliberate planning decisions (D5, D3). The plan includes a
README step (Step 8), as required. No Critical findings.
