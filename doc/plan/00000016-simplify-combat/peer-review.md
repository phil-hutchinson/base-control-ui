# Peer Review — 00000016 Simplify combat

## Summary

The branch delivers all three rules changes the story asks for: attack range is
now §6's movement range (derived from `reachFrom`, with the eight-neighbour
table deleted), a winning attacker advances along its lane to the furthest
square it may legally end on and wakes nodes on the way, and a ship may take
only one action per turn (`movedThisPly` → `actedThisPly`, with attacks now
recording into it). `rules.md` moved to 0.8 in its own first commit alongside
the changelog entry, `RULES_VERSION` and the README sentences that would
otherwise have contradicted it; the nine commits map one-to-one onto the plan's
nine steps, each with a Notes line, and the plan's Step 9 is the README
accuracy pass the review process asks for. Rule logic was checked
section-by-section against `rules.md` 0.8 and no contradiction or unstated rule
was found.

`npm run typecheck` passes. `npm run lint` passes with no findings.
`npm test` passes: 40 files, 648 tests, including `fullGame.test.ts` unchanged
and still completing at the expected ply. (`npm run format:check` also passes.)

One Major finding: the rewritten `assertFightInvariants` — the story's and the
plan's designated safety net over the advance — checks the winner's square
against a set derived from the very value that placed it there, so the
"landed off its lane" invariant cannot fire in production. The remaining
findings are minor: comment-convention breaches (story narration and a recorded
rejected approach in `src/`), a stale doc comment, a README sentence that
generalises the advance to every winner, and a UI redundancy the rule change
introduces.

Noted but not filed as a finding: the plan's Decision 2 deviates from
`story.md`'s "§6, §8.5 and §4.1 are unchanged" by correcting three consequential
sentences in those sections. The deviation is explicitly reasoned in the plan,
named in the changelog entry as a correction rather than a new rule, and is
sound — a ruleset that contradicts itself would be worse.
