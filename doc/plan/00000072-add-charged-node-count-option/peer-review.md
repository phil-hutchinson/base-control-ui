# Peer Review — Story 00000072, A chosen number of charged nodes

## Summary

The branch turns the board's charged-node count into a pre-play choice (five
or four, five the standard game): `rules.md` goes to 0.30 with a single
changelog entry and a matching `RULES_VERSION`, `TARGET_CHARGED_NODES` is
replaced by `ChargedNodeCount` / `CHARGED_NODE_COUNTS` /
`DEFAULT_CHARGED_NODE_COUNT` / `isChargedNodeCount`, the count is stored on
`GameState` and threaded through `dealOpeningBoard`, `runCharging`, the
`new-game` intent, `useAppScreen` and a fourth start-screen group, and the HUD
pip row is re-cut to `min(ship count, charged-node count)`. `npm run typecheck`
is clean, `npm run lint` is clean, and `npm test` passes (59 files, 1114
tests). The eleven plan steps are all committed and the plan's decisions and
stipulations are honoured in the code — S6 (re-measured, not re-fitted; one
bound was nudged, see #3), S8 (`--region-extent` untouched, only its comment
corrected), S10 (exactly one `## 0.30` changelog entry, one version bump), and
the fixture pins to `chargedNodeCount: 4` are honest: every pinned fixture is
one whose test names a specific shortfall or "board at its target", and not one
assertion in those files was edited to accommodate the new default. Step 11
included the required README update. The findings below are mostly about
comments and test naming that Step 11's sweep missed, not about the behaviour
itself.
