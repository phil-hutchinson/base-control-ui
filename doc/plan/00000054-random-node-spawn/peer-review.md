# Peer Review — Story 00000054, Nodes that move around the board

## Summary

The branch retires fixed sites and makes nodes mortal and mobile: `rules.md`
goes to 0.20 in its own commit ahead of the code, `src/` is renamed
site/active/dormant → node/inactive/depleted, `nodePlacement.ts` implements
§3.2's five constraints plus the fallback, `dealOpeningBoard` deals fifteen
nodes at drawn squares in a fixed 30-step draw order, and `endOfTurn.ts` step
6 retires a recovered node and writes a replacement elsewhere, emitting a
`node-replaced` effect that the end-of-turn announcement speaks.

`npm run typecheck` passes (no output). `npm run lint` passes (no findings).
`npm test` passes: 54 files, 938 tests, ~60s. All three were run from the
repository root at the reviewed commit.

Checks specifically requested and found sound, so not raised as comments:

- **Replay determinism.** Every draw is a fixed number of seed steps and
  every ordered walk comes from `ALL_SQUARES`. `legalNodePool`,
  `dealOpeningBoard`, `runChargeDraw` and `runEndOfTurn` use `Set`/`Map` only
  for membership lookups, never for iteration. The one remaining
  `Object.keys(state.nodes)` in production code (`ply.ts`'s fight invariant)
  only orders error messages on an already-failing path. The fallback branch
  in `legalNodePool` changes which pool is drawn from but not how many seed
  steps are consumed.
- **The retirement sequence.** Step 6 removes the entry, then builds the pool
  from `nodeSquares(workingState)` with the retiring square excluded, then
  draws, then writes — exactly D15's order — and iterates the entry snapshot
  `depletedBeforePly` so two retirements complete one after the other in
  board order, per D16.
- **One out, one in.** Removal and write are in the same block with no early
  return between them; `legalNodePool` cannot return an occupied square, so a
  replacement can never be written without a retirement. The only path where
  a node leaves without a replacement is `legalNodePool`'s deliberate
  `RangeError`, which aborts the whole ply rather than committing a
  fourteen-node board.
- **README step.** The plan does include one (Step 10), and `README.md` was
  rewritten; no comment raised.
- **D7, D12 and D19** were checked as instructed and are not raised: the
  absent planet/bay adjacency constraint is correct, `NodeMarker.tsx`'s
  `"Dormant"`/`"Active"` quotes are deliberate, and the seven repaired
  fixtures now state the board they need rather than relying on the retired
  off-list trick. Step 5's six deleted tests described a constant that no
  longer exists and the 20,000 → 3,000 deal reduction still yields ~15,000
  drain and ~30,000 pressure draws against a 3% margin — both defensible.
